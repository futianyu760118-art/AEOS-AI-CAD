# AEOS AI-CAD｜RUGGED-H6000 高保真逆向建模与开源工具选型执行方案

- 版本：V1.0
- 日期：2026-11-13
- 项目归属：AEOS AI-CAD；后续纳入 M04 研发自治中心工作流
- 目标：真实生成、可编辑、可验证、可复现的高保真 STEP/STP

## 1. 项目目标

从 RUGGED-H6000 多角度产品图片和工程尺寸恢复可编辑三维 CAD，形成有效 STEP/STP 装配模型，并沉淀可复用的 AI-CAD 工作流。

交付目标：
- 正面、背面、侧面、斜视视角保持同一三维结构一致；
- 主要零件可独立选择、编辑和修改尺寸；
- 输出原生 CAD、STEP/STP、GLB 预览、二维工程图和 BOM；
- 形成可复制到其他 AEOS 产品研发项目的逆向设计能力。

核心原则：先保证几何保真度，再保证参数化能力，最后完成工程化。不能以成功导出 STEP 作为模型验收标准。

## 2. 当前基线与真实状态

## 3. 开源工具路线

### A 组：img2cad
仓库：https://github.com/YUI-TIEN/img2cad

定位：图像观察、轮廓提取、视觉智能体辅助建模、参数化 CAD 生成与迭代复核。必须核对实际 README、依赖、许可证和可运行命令。它不是单条一键照片转 STEP 的推理命令，需要视觉 Coding Agent 参与观察、计划、建模和修改。

### B 组：Agentic CAD
仓库：https://github.com/dancher00/agentic-cad

定位：多图片联合重建、视觉/几何反馈、CAD 程序生成与 STEP 输出。需检查 GPU、模型服务、模型权重和外部 API 要求。

### C 组：工程几何工具
- FreeCAD / OpenCascade：BREP 几何内核、曲面/实体修正、装配、STEP 导出和几何有效性验证；
- CadQuery / build123d：参数化特征建模和可重复构建；
- PartCAD：后续评估零件、装配、依赖和版本管理。

选型不得只看 Stars、宣传截图或单一演示，必须以同源输入的真实结果、可复现性、许可、工程可编辑性和人工修正成本为依据。

## 4. 目标执行流程

1. **输入冻结**：冻结正面、背面、侧面、斜视、工程图、已知尺寸、坐标系和 G0 轮廓基线。
2. **预处理**：保留原图，标注关键轮廓和特征点，确认相机视角、尺度约束和视图间冲突。
3. **A/B 重建**：分别运行 img2cad 与 Agentic CAD，保存未经人工修正的初始输出、日志、参数、源码 Commit 和模型服务信息。
4. **工程修正**：导入 FreeCAD/OpenCascade，修复曲面、边界、实体和装配关系；保留原始模型与修正版差异。
5. **验证**：固定视角渲染，与原图叠加；计算轮廓、局部 ROI、边缘和尺寸误差；检查 BREP、实体数量、干涉和装配位置。
6. **交付**：原生 CAD、STEP/STP、GLB、工程图、BOM、评分报告、安装说明和完整日志。

## 5. 统一 A/B 测试协议

- 两组使用同一套原始参考图片、同一工程尺寸、同一 G0 轮廓数据和同一坐标系；
- 禁止事后换素材、换范围或用仓库示例图替代项目输入；
- 分别保存工具原始生成模型、统一工程修正模型和最终交付模型；
- 单独评价主壳、中央反光杯、左右橙色护角、左右侧灯、铰链、提手、底座及背部电池/接口区域；
- 记录人工干预工时、修改特征数、脚本改动量、失败重试次数、生成耗时和 API 成本；
- 记录仓库 Commit SHA、许可证、依赖版本、模型权重、API/服务配置、运行命令、日志和输出文件哈希；
- 未运行或未生成文件的方案标记为 NOT_RUN，不得用 0 分作评测结论；
- 不得为了提高分数把不同模型强行形变贴回原图。

## 6. 首轮验收目标

| 指标 | 首轮目标 |
|---|---:|
| 正面轮廓 IoU | ≥95% |
| 背面轮廓 IoU | ≥95% |
| 侧面轮廓 IoU | ≥93% |
| 斜视轮廓 IoU | ≥90% |
| 已知总体尺寸误差 | ≤1% |
| 关键结构位置误差 | ≤总体尺寸的 1% |

同时检查曲面边界/法向连续性、曲率突变、边缘波浪、非流形、薄片面、异常小面、STEP 实体有效性、装配干涉和主要零件可编辑性。上述数值是工程目标，不是已实现成绩；资料不足时标记不可判定，不得虚构精度。

## 7. RUGGED-H6000 零件建模顺序

1. 主灯外壳、中央反光杯/LED 面板、左右侧灯组件；
2. 橙色防护角、左右铰链、提手和握把；
3. 可拆卸电池包、后盖、电源接口、开关及控制组件；
4. U 形支架、底座、枢轴、紧固件和整机装配。

左右对称件可建立母件/镜像关系，但必须验证原图是否完全对称。不可见内部结构必须标记为假设，不得伪装为已从图片恢复的真实结构。

## 8. Work 联网执行要求

执行环境使用 ChatGPT Work 的联网云端浏览器/电脑环境。先检查仓库、许可证、依赖和环境，再运行官方最小示例，最后使用 RUGGED-H6000 真实图片建模。

如需付费 API、云 GPU、模型托管或新增云资源，先说明供应商、规格、预估费用和权限需求，获得批准后再启用。缺少 GPU、模型权重、API Key、授权或图片时，记录阻碍、错误日志和最小补充条件。必须区分“已安装、已运行示例、已运行本项目、已生成 STEP、已通过几何验证、已达到保真目标”六种状态。

## 9. 项目完成定义（Definition of Done）

- 工具层：至少两种候选路线完成真实安装与运行；源码版本、许可证、依赖和日志可追溯；
- 模型层：至少一条路线在真实 RUGGED-H6000 图片上生成新的 CAD/STEP，并保留原始与修正版本；
- 保真层：多视图和关键局部达到约定目标；未达标项有差距、原因和整改计划；
- 工程层：主要零件可独立编辑，装配关系合理，STEP 通过几何有效性检查；
- 归档层：模型、工程图、BOM、评分、日志、安装说明和版本记录完整。

最终原则：项目持续推进至通过工程验收；安装成功、脚本生成成功或单一视图高分均不构成项目完成。
